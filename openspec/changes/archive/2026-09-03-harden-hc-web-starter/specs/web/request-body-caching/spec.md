## Purpose

为请求体缓存增加大小上限：可缓存大小范围内的请求体完整读入内存以便重复读取（日志/XSS/幂等）；超限请求体降级为不缓存、直接消费原始流，避免大请求导致 OOM。

## ADDED Requirements

### Requirement: 可配置的缓存体上限

系统 SHALL 提供请求体可缓存大小上限的配置（`hc.web.max-cached-body-size`，默认 2MB）。请求体已知大小不超过上限时，SHALL 被完整读入缓存，wrapper 可重复提供输入流。

#### Scenario: 上限内请求体可重复读取

- **WHEN** 请求体大小不超过配置上限（如 1MB < 2MB）
- **THEN** 请求体被缓存，多次读取输入流均返回完整相同内容

### Requirement: 超限请求体降级不缓存

系统在请求体超过缓存上限时 SHALL 放弃整体缓存（内存中不持有超限体），读取输入流的行为降级为消费原始请求流；该请求的包装器不得因请求体过大而抛出 OOM/内存异常。

#### Scenario: 超限大请求体不 OOM

- **WHEN** 请求体远大于缓存上限（如 10MB > 2MB）被包装
- **THEN** wrapper 构造成功且未将超限请求体整体载入内存（不 OOM），且该请求上基于缓存的重复读取不可用（日志切面读取时明确无缓存体）

#### Scenario: 声明大小未知时二次防护

- **WHEN** 请求未声明 Content-Length 或声明的长度不可信，读入后发现实际大小超过上限
- **THEN** 缓存被丢弃并转为"不缓存"状态，不保留超限内容于内存
